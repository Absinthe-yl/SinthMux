# ADR-0001：远程连接架构

状态：已采纳
日期：2026-09-21

#### 一、决策背景
##### 1.1 问题
SinthMux 需要让家庭电脑、办公电脑和云服务器在没有公网 IP、没有端口映射的情况下接入同一个公网 Hub，并允许手机、平板和电脑通过浏览器访问。

##### 1.2 候选方案
（1）Hub 主动 SSH：要求 Hub 能直接访问远程设备，NAT 和防火墙适应性差。

（2）SSH Reverse Tunnel：成熟，但端口管理、`authorized_keys` 权限和横向移动风险会进入产品核心。

（3）WireGuard/Tailscale/Headscale：安全且可直连，但控制面、DERP、ACL 和客户端部署超过首版范围。

（4）Agent 主动 mTLS WebSocket：只需出站 `443`，浏览器兼容好，Hub 能统一路由、授权和审计。

#### 二、最终决策
##### 2.1 选定方案
采用 Agent 主动建立的 mTLS WebSocket 作为主连接协议，浏览器通过 HTTPS/WSS 连接 Hub。

##### 2.2 关键约束
（1）Agent 不监听公网端口。

（2）设备身份由 Hub 签发的短期证书决定，不信任 Agent 自报身份。

（3）终端浏览器连接使用一次性短期票据。

（4）Hub 是受信任控制面，可以看到终端明文。

（5）协议必须版本化，并允许未来增加 QUIC 传输实现。

#### 三、影响
##### 3.1 正面影响
（1）适用于 NAT、家庭宽带和大多数云安全组。

（2）远程设备不需要开放 SSH 或 Agent 端口。

（3）Hub 能集中完成权限、审计、限流和设备吊销。

（4）Go Agent 可以作为小型单文件程序发布。

##### 3.2 代价
（1）Hub 成为关键可信组件和流量中继点。

（2）必须处理大量长连接、流量背压和断线恢复。

（3）mTLS CA、证书轮换和吊销增加实现复杂度。

（4）Hub 故障会影响所有新连接，因此增强阶段需要高可用和在线路由共享。
